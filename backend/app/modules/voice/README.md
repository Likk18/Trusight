# TRUSIGHT — Voice Analysis Service

Standalone FastAPI microservice implementing **only the Voice Analysis
module** of TRUSIGHT, a multimodal truth-verification prototype. The full
system also has separate Text Analysis and Video Analysis modules (owned by
teammates); this service does not depend on them and can be built, run, and
tested entirely on its own.

## What this module does — and does not — do

Given an uploaded audio recording, this service extracts acoustic/vocal
features (pitch, jitter, shimmer, pauses, tempo, energy, spectral shape,
MFCCs) and feeds them into a Random Forest classifier to produce a
**deception-likelihood score**, a **confidence value**, and a short list of
**human-readable acoustic observations**.

**Important scientific caveat:** vocal cues alone are not a reliable lie
detector. Decades of deception-detection research show that acoustic
features correlate weakly and inconsistently with actual truthfulness, and
professional polygraph/voice-stress-analysis tools are widely considered
scientifically unreliable for real-world lie detection. This module:

- estimates deception *likelihood from vocal acoustic cues only*,
- is designed as **one signal among several** in the larger multimodal
  TRUSIGHT system (voice + text + video, combined downstream),
- does **not** render a final truth/lie decision by itself, and
- should not be used, as-is, to make consequential decisions about a real
  person (e.g. hiring, legal, or law-enforcement contexts).

The bundled model (see [Model description](#model-description) below) is a
prototype trained on synthetic data by default and exists to prove the API
pipeline works end-to-end — not to make claims about real speech.

## Project overview

- **Framework:** FastAPI + Uvicorn
- **Feature extraction:** Librosa (MFCCs, tempo, energy, spectral shape) and
  Praat-Parselmouth (pitch/F0, jitter, shimmer, pause/silence detection)
- **Model:** scikit-learn `RandomForestClassifier`, persisted with `joblib`
- **Scope:** voice only — no text or video processing lives in this repo

## Installation

Requires **Python 3.11 or 3.12 or 3.13** from [python.org](https://python.org) (the official Windows installer).

> ⚠️ **Windows users:** Do **NOT** use Anaconda Python for this project. Anaconda ships an
> experimental MINGW-built `numpy` that causes runtime crashes (`invalid value encountered in exp2`).
> Use the official CPython installer from python.org instead.

### Option A — Windows one-click setup (recommended)

```bat
cd voice_service
.\setup.bat
```

The script automatically finds the correct CPython installation, creates a `.venv`,
installs all dependencies, and trains the synthetic prototype model.

### Option B — Manual setup (any OS)

```bash
cd voice_service

# Create and activate virtual environment
python -m venv .venv
source .venv/bin/activate          # Linux/macOS
# .venv\Scripts\activate           # Windows

# Install dependencies
pip install -r requirements.txt

# Train the model (required before first run)
python train_model.py
```

On Debian/Ubuntu you also need `libsndfile1` for audio decoding
(already handled automatically inside the Docker image):

```bash
sudo apt-get install -y libsndfile1 ffmpeg
```


## Training the model

A model must exist at `app/models/deception_model.pkl` before `/analyze`
will serve predictions (it returns HTTP 503 otherwise).

```bash
# Prototype mode — trains on a synthetic placeholder dataset so you can
# exercise the full API immediately. NOT derived from real speech.
python train_model.py

# Real training — point at a folder with truthful/ and deceptive/
# subfolders of labeled .wav files:
python train_model.py --data-dir path/to/dataset
```

Expected structure for `--data-dir`:

```
dataset/
├── truthful/
│   ├── clip001.wav
│   └── ...
└── deceptive/
    ├── clip001.wav
    └── ...
```

### Sourcing real labeled data

`sample_audio/truthful.wav` and `sample_audio/deceptive.wav` are
**synthetically generated tones**, not real speech — they exist only so the
API can be smoke-tested immediately after cloning. For real training data,
look into:

- **Real-Life Trial dataset** (Pérez-Rosas et al., 2015) — courtroom trial
  clips labeled truthful/deceptive; requires a request to the authors.
- **Columbia-SRI-Colorado (CSC) Corpus** — deceptive and non-deceptive
  speech collected under controlled conditions; access via LDC.
- Any IRB-approved, consented deception-speech corpus your institution has
  access to.

Always verify licensing and consent terms before using any dataset, and
retrain (`python train_model.py --data-dir ...`) before drawing any
conclusions from this service's output.

## Running

After setup (either via `setup.bat` or manual steps):

```bash
# Activate the virtual environment first
source .venv/bin/activate        # Linux/macOS
# .venv\Scripts\activate         # Windows

# Then start the service
uvicorn app.main:app --reload
```

Or without activating:

```bash
# Linux/macOS
.venv/bin/uvicorn app.main:app --reload

# Windows
.venv\Scripts\uvicorn app.main:app --reload
```

The service starts on `http://127.0.0.1:8000`. Interactive Swagger docs are
available at `http://127.0.0.1:8000/docs`, and the raw OpenAPI schema at
`/openapi.json`.

### Verify setup

Before starting the server, you can run the end-to-end smoke test:

```bash
python verify_setup.py
# Expected: 17 passed, 0 failed
```


## API

### `GET /`  and  `GET /health`

Liveness check.

```json
{
  "service": "Voice Analysis Service",
  "status": "running"
}
```

### `POST /analyze`

**Content-Type:** `multipart/form-data`
**Field:** `audio` — the recording file (`.wav`, `.flac`, `.ogg`, `.mp3`, `.m4a`)
**Optional query param:** `include_features=true` — also returns the raw
extracted acoustic feature vector.

#### Example request

```bash
curl -X POST "http://127.0.0.1:8000/analyze" \
  -F "audio=@sample_audio/truthful.wav"
```

#### Example response

```json
{
    "verdict": "Truthful",
    "score": 0.34,
    "confidence": 0.66,
    "explanation": [
        "Stable pitch variation",
        "Normal speech tempo",
        "Few hesitation pauses"
    ],
    "features": null
}
```

`score` is the model's estimated probability of deception (0 = truthful,
1 = deceptive); `verdict` is derived from `score >= 0.5`.

#### Error responses

| Status | Meaning |
|---|---|
| 400 | Missing file, unsupported format, empty/too-large upload |
| 422 | File passed validation but audio decoding or feature extraction failed |
| 503 | No trained model loaded (run `train_model.py`) |
| 500 | Unexpected internal error |

## Model description

- **Algorithm:** `RandomForestClassifier` (scikit-learn), 200 trees, max
  depth 10, balanced class weights.
- **Input:** a fixed-order 42-dimensional feature vector — 4 pitch stats, 2
  voice-quality stats (jitter/shimmer), 4 timing stats, 6 energy/spectral
  stats, and 26 MFCC mean+std values (13 coefficients each). Exact ordering
  is defined once in `app/feature_extractor.py::FEATURE_ORDER` and reused
  by `train_model.py` so training and inference never drift apart.
- **Output:** `predict_proba` over two classes (0 = Truthful, 1 =
  Deceptive); the deceptive-class probability is returned as `score`.
- **Default shipped weights:** trained on synthetic feature data (see
  `train_model.py`), for pipeline demonstration only.

## Limitations

- Vocal-only deception cues are weak and noisy predictors of real
  truthfulness; treat `score` as one modality's opinion, not a verdict.
- The shipped model is trained on synthetic data by default and has no
  demonstrated validity on real speech until retrained on real labeled data.
- Pitch/jitter/shimmer extraction can degrade on very short, noisy, or
  whispered recordings; the service degrades gracefully (returns 0-valued
  sub-features) rather than crashing, but downstream scores may be less
  meaningful in those cases.
- No speaker diarization — assumes a single speaker per clip.
- No language-specific tuning; feature extraction is language-agnostic but
  was not validated across languages or accents.

## Future improvements

- Retrain on a real, IRB-approved deception-speech corpus.
- Add calibration (e.g. Platt scaling) so `score` better approximates a
  true probability rather than a raw Random Forest vote fraction.
- Speaker diarization for multi-speaker interview recordings.
- Confidence intervals / uncertainty estimates alongside the point score.
- Integration contract with the Text and Video modules for the final
  multimodal fusion decision (owned outside this repo).
